# 笔上元气骑士 · 屏幕适配

> 版本：v0.1（2026-10-26）
> 适用范围：`ui/src/**` 全部页面与 `ui/src/services/game/**` 渲染/触摸层。
> 继承来源：三角洲摸金模拟器 `docs/屏幕适配.md`（真机结论见 [技术规范/屏幕适配.md](技术规范/屏幕适配.md)）。
> 结论先行：**逻辑宽固定 960，逻辑高不再假设 266，一切按设备物理比例实时换算**。

---

## 一、官方依据

- `$falcon.env.deviceWidth / deviceHeight` = **设备物理分辨率宽/高**（官方 `04-posc-docs/jsapi/env/global.md`）。
- `app.js` 的 `setViewPort(960)`：把 960 逻辑宽映射到设备物理宽，即 **1 逻辑 px = 物理宽 / 960**。
- 因此页面逻辑高：

```
pageH = round(960 × 物理短边 / 物理长边)      // 横竖屏通用
```

- 设计基准 **960 × 266**；实际逻辑高区间约 **240 ～ 576**（见第五节设备矩阵）。

---

## 二、计算链路

```
app.onLaunch                                        ui/src/app.js
  ├─ setViewPort(960)                               逻辑宽 → 物理宽
  ├─ screenInfo()                                   ui/src/services/screen.js
  │    env($falcon.env.deviceWidth/Height, 100..5000)
  │      → window.innerWidth/Height（Falcon 页面通常没有 window）
  │      → document.documentElement
  │      → 960×266 兜底
  │    source = env | window | document | fallback
  │    logicalHeight = round(960 × shortSide / longSide)，下限 120
  └─ 日志 [screen] logical=960x<pageH> physical=WxH source=<来源>

页面布局：纯 CSS vw/vh（不写死 266）
game.vue：canvas 物理像素 + engine.setViewport(960, pageH) + 触摸换算
日志：启动一行 [screen]，游戏页首帧 [game-screen]
```

`screen.js` 对外 API：

```js
screenInfo()  // { env, win, doc, physical, source, logicalWidth, logicalHeight, profile }
pageSize()    // { w: 960, h: pageH }（诊断/引擎/触摸用）
screenText()  // 一行诊断串，写日志/关于页
readPhysical()// { w, h } 物理分辨率（兼容旧调用）
```

> **已知不一致（待统一）**：`ui/src/screen-profile.js` 的 `logicalHeightForPhysical()` 会把结果**抬到最低 266**，而 `services/screen.js` 的 `logicalHeight()` 不抬（下限 120）。短屏（240）下两者结果不同；页面/引擎应统一使用 `services/screen.js`，`screen-profile.js` 仅作历史兼容，**不要在新代码里用**。

## 三、布局单位规则（页面）

| 用途 | 单位 | 说明 |
|---|---|---|
| 根容器 / 背景 / 遮罩 / 覆盖层 | `100vw` × `100vh` | 一定铺满，不裁切 |
| 横向尺寸 / 横向 margin、padding | `vw` | 100vw = 960 逻辑宽；1 设计 px = 0.10417vw |
| 纵向尺寸 / 纵向 margin、padding / 字号 / 行高 | `vh` | 100vh = pageH；1 设计 px = 100/pageH vh |
| 圆形、方形控件（宽高相同） | 两个方向都用 `vh` | 避免被拉成椭圆 |
| 滚动区 / 列表 / 面板高度 | `vh` 或由内容撑开 | 短屏可滚，不写死 266 |
| 游戏页 DOM 控件 | `vh` | 与 canvas 同源 |

示例（设计基准 266 高时）：

```
1 设计 px（横）= 100/960 vw ≈ 0.10417vw
1 设计 px（纵）= 100/266 vh ≈ 0.37594vh
```

- 旧固件不支持 `vw/vh` 时，用前置的 `px` / `%` 降级声明兜底（X3S 黑屏修复经验）。
- **不要再**用 JS 按 `pageH - 常量` 计算 px 布局；数值只保留给 canvas、引擎视口、触摸命中与日志。

## 四、游戏页（Canvas）适配

### 4.1 canvas 物理像素

```html
<canvas class="game-canvas" :width="canvasW" :height="canvasH"></canvas>
```

- `canvasW/canvasH` = 设备物理像素（`screenInfo().physical`），不是逻辑 960×266；
- 样式仍 `width:100vw; height:100vh`，由运行时把物理像素铺满屏幕；
- 引擎入口（契约 §6）：

```js
g.setCanvasPixels(physW, physH)   // canvas 后备缓冲物理像素
g.setViewport(960, pageH)         // 逻辑视口
g.render()                        // 内部 setTransform 完成物理像素缩放
```

### 4.2 引擎视口

- 逻辑视口宽固定 960，高 = `pageH`；
- 每帧可按 canvas 实际像素反算：`viewH = canvasH / (canvasW / 960)`，保证 1:1 铺满、不 letterbox；
- 相机、HUD、剔除、暂停遮罩全部用 `viewW/viewH`，**不要再出现写死 266 的分支**。

### 4.3 触摸换算

- 原生路径：`createTwoFinger({ width: 960, height: pageH, rotation: 90 })`，与引擎同源；
- DOM 降级路径：触摸坐标为物理像素时，逻辑坐标：

```
logicalX = physX × 960 / physW
logicalY = physY × pageH / physH
```

- 摇杆、开火/技能/换枪/交互/暂停热区全部用逻辑坐标定义，再按上式反算命中；
- 真机上若 `screenX/clientX` 单位不确定，先打一行 `[touch] first ...` 日志再定位（旧项目经验：可能有 ≈24px 偏移，native 路径不受影响）——**待真机验证**。

## 五、设备矩阵（继承旧项目结论 + 本作换算）

`pageH = round(960 × 短边 / 长边)`：

| 物理分辨率 | 物理比例 | 逻辑视口 | 说明 | 验证状态 |
|---|---|---|---|---|
| 960 × 266 | 3.61:1 | 960 × 266 | 设计基准（X3s 类） | 旧项目已验证 |
| 960 × 240 | 4:1 | 960 × 240 | 更矮短屏 | 旧项目测试覆盖 |
| 960 × 320 | 3:1 | 960 × 320 | 更高屏 | 旧项目测试覆盖 |
| 936 × 280 | 3.34:1 | 960 × 287 | y02-1 / X7 Pro（rk 主真机） | 旧项目真机已验证 |
| 800 × 240 | 3.33:1 | 960 × 288 | CVI 类小屏 | 旧项目测试覆盖 |
| 280 × 936 | 3.34:1 | 960 × 287 | 竖屏读数（短边换算） | 旧项目测试覆盖 |
| 800 × 480 | 5:3 | 960 × 576 | X6P（melon，归 rk 家族） | 旧项目实测，修复后待复验 |

约束：

- 布局必须同时兼容 **240（最矮）～576（最高）**；短屏优先保证 HUD/按钮完整，高屏允许留天空/地面（不强制铺满）；
- 物理尺寸非法（0、负数、>5000）时 `screen.js` 过滤并落到兜底 960×266；
- 本作新增页面（大厅/角色/图鉴/设置/结算）与游戏 HUD 都要按此矩阵自查。

## 六、诊断与验证

### 6.1 启动日志（每次冷启动一组）

```
[app launch] app launch, platform=... model=... screen=936x280 fw=...
[screen] logical=960x287 physical=936x280 source=env
```

- `source=env` 为正常；`window/document/fallback` 说明环境读数缺失，需要用户提供 `screenInfo` 全量；
- 游戏页首帧应有 `[game-screen] pageH=... canvas=... engineView=960x...`（由 `game.vue` 输出）。

### 6.2 验证方法

1. 用目标设备启动，取 `[screen]` 行，确认 `logical=960×N` 与本文矩阵一致；
2. 逐页检查：根容器铺满、底部按钮不被裁、弹窗完整可见、无横向滚动；
3. 游戏页检查：画面无黑边/拉伸；摇杆中心与实际手指位置一致；四角 HUD 不出屏；
4. 切后台/回前台、熄屏再亮：视口不丢、触摸不错位。

### 6.3 自动化

- 本作已迁移屏幕适配测试：`ui/scripts/test-screen.mjs`，**22 条断言**，覆盖 960 逻辑宽换算（936×280→287、960×266、960×240、960×320、800×240→288、280×936→287、800×480→576）、竖屏短边换算、异常值过滤、来源优先级（env→window→document→fallback）。
- 换算公式与旧项目一致；**真机矩阵仍待实测**（自动化只证明函数逻辑，不证明设备渲染）。

## 七、已知风险（待真机验证）

1. `$falcon.env.deviceWidth/Height` 语义是否在所有固件上都是**物理像素**（若是逻辑值，canvas 会纵向拉伸）；
2. 深层节点 `height:100%` 在部分节点不可靠，所以面板/滚动区要显式 `vh`，不要依赖百分比链；
3. DOM 触摸降级路径优先 `screenX/screenY`，其单位若为物理像素，摇杆可能有最多 ≈24px 偏移；
4. `vh/vw` 官方支持但个别旧固件行为异常——保留 `px/%` 降级声明；
5. X6P（800×480 → 逻辑 960×576）修复后未在本作复验；
6. 竖屏安装（240×960 等）时 `setViewPort(960)` 的实际表现未验证。

> 以上未验证项在 [还原度验收.md](还原度验收.md) 中按「部分/待真机验证」计分，不得写成已通过。
