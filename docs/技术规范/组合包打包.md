# 组合包打包（按家族组合包）

> 适用范围：`node scripts/build-amr.mjs --merge`（家族组合包）与 `--merge-cross`（跨家族实验包）。
> 2026-10-19 官方规范对齐重构后的最终语义；命令以 `node scripts/build-amr.mjs --help` 为准。
>
> 一句话：**组合包按「家族」出，每个家族一个 `.amr`**；同一个包里放该家族多个官方代号的
> `<架构>-<代号>/` 库目录，JS 就是该家族单包（原生模块集合完全一致）。
> 跨家族合并（rk+cvis 共用一份 JS）只保留为实验开关，**不发布**。

---

## 一、为什么按家族组合（而不是官方那种跨家族单包）

官方 `build_merge()` 的跨家族组合包，前提是**各设备代号使用同一套 JSAPI bridge 模块**：
应用 JS 里 `import` 的模块对所有代号都成立，运行期由框架/PMS 按设备代号选中并解压对应目录的 so。

本项目不满足这个前提：

| 家族 | 包内原生库 | JS 静态 import |
|---|---|---|
| rk（aarch64/glibc） | panet + Eric + twofinger + updater | `panet` / `Eric` / `updater` |
| cvis（armv7/glibc） | bridge + updater | `updater`（bridge 由宿主 dlopen，不静态 import） |
| rka（armv7/uClibc） | bridge(uClibc) + updater | `updater` |

ESM 的静态 import 在模块求值前必须全部解析，**同一份 app.js.bin 无法同时满足 rk 与 arm 家族**：

- rk 的 JS 写了 `import 'panet'` → 装到 cvis 设备上整页白屏（try/catch 拦不住）；
- arm 家族的 JS 到 rk 上会失去 panet → 文件读取/双指/安装能力降级（真机实测，见 §七）。

所以正式产物改成**按家族组包**：一个家族内部多代号共用一份 JS（原生模块集合相同），
只把库按官方代号目录打包。代价是：**跨家族换机仍要装对应家族的包**；收益是原生能力不降级。

---

## 二、前置条件

- Node.js ≥ 22、pnpm 10（`pnpm -C ui install` 已装好依赖）
- 库物料齐全：`native/libs/arm-coco/`（cvis）、`native/libs/arm-y09/`（rka）、
  `native/libs/arm64-y02-1/`（rk，可选）
- **zig**：`_ref/zig/z/zig.exe`（或环境变量 `ZIG_EXE`）——组合包需要对 bridge 执行
  `objcopy --strip-all`；找不到 zig 时构建在预检阶段直接失败

## 三、命令

```bash
# 家族组合包（默认：cvis + rka，各出一个 amr）
node scripts/build-amr.mjs --merge

# 指定家族（可含 rk；rk 家族包可选）
node scripts/build-amr.mjs --merge --merge-targets cvis
node scripts/build-amr.mjs --merge --merge-targets cvis,rka
node scripts/build-amr.mjs --merge --merge-targets rk

# 只暂存不打包（检查 ui/libs 目录结构；ui/libs 最终保留“最后一个家族”的暂存结构）
node scripts/build-amr.mjs --stage --merge
node scripts/build-amr.mjs --stage --merge --merge-targets cvis

# 跨家族实验包（旧 --merge 行为；rk 原生能力会降级，勿发布）
node scripts/build-amr.mjs --merge-cross
node scripts/build-amr.mjs --merge-cross --merge-targets rk,cvis

# 其它可选参数
node scripts/build-amr.mjs --merge --verify          # VERIFY_BUILD=true（真机自检构建）
node scripts/build-amr.mjs --release --merge         # 先递增 patch 再打组合包
node scripts/build-amr.mjs --merge --skip-so-check   # 跳过 so 预检（确知库正确时，风险自负）
node scripts/build-amr.mjs --help
```

环境变量：`MERGE=1`（家族组合包）、`MERGE_TARGETS=cvis,rka`、`MERGE_CROSS=1`（跨家族实验）、
`VERIFY_BUILD=1`、`SKIP_SO_CHECK=1`、`PNPM_CMD`。

> 组合包模式不能与 `--targets` 混用（会报错）；组合包家族请用 `--merge-targets`。

## 四、产物与目录布局

| 产物 | 体积（v1.1.52 实测） | `libs/` 布局 |
|---|---|---|
| `dist/miniapp-merged-cvis-1.1.52.amr` | 2,178,939 B（2.08 MB） | `arm/`、`arm-coco/`、`arm-plum/`，每目录 `libjsapi_bridge.so`(281,948 B) + `libjsapi_updater.so`(35,480 B) |
| `dist/miniapp-merged-rka-1.1.52.amr` | 2,193,883 B（2.09 MB） | `arm/`、`arm-y09/`、`arm-y09p/`，每目录 `libjsapi_bridge.so`(359,800 B) + `libjsapi_updater.so`(35,268 B) |
| `dist/miniapp-merged-rk-<版本>.amr`（可选） | — | `arm64/`、`arm64-orange/`、`arm64-y02-1/`，每目录 panet/Eric/twofinger/updater（不 strip） |
| `dist/miniapp-merged-cross-<版本>.amr`（实验） | — | 多家族目录同包，**勿发布** |

- 每个包共 **928 个条目**（`app.js.bin` + 918 张 PNG + 6 个库 + manifest 等）。
- 每个家族包内 **6 个库文件**（3 个目录 × 2 个库）；目录名严格来自 profile 的官方代号集。
- 根目录**不得有任何 `.so`**；`libjsapi_bridge.so` 只允许在 `<架构>-<代号>/` 子目录内。
- 体积上限 10MB（脚本硬校验，超限直接报错）。

## 五、strip（组合包必需）

组合包暂存时对 `libjsapi_bridge.so` 做 `zig objcopy --strip-all`，**只 strip 副本，源库不动**：

| 家族 | strip 前 | strip 后 | 省 |
|---|---|---|---|
| cvis | 5,856,772 B | **281,948 B** | 5,574,824 B（≈95.2%） |
| rka | 471,256 B | **359,800 B** | 111,456 B（≈23.6%） |

- 工具：`scripts/elf-strip.mjs` → `_ref/zig/z/zig.exe objcopy --strip-all <src> <dst>`
- strip 后自动校验 ELF 架构与 libc 类型**不变**（变了直接抛错）。
- rk 家族包按现状**不 strip**（panet/Eric 是已真机验证的库，保持原样最稳）。
- 单包（`--targets`）也**不 strip**（见 [官方规范对齐.md](官方规范对齐.md) 偏差 D4）。

## 六、构建流程（脚本自动做什么）

`--merge` 对每个家族依次执行（默认 cvis → rka）：

1. **so 平台预检**：校验该家族库物料存在、架构与 libc 匹配；组合包模式额外检查 zig 可用。
2. **生成版本文件**：`res/version.js` 按该家族生成（`platform=cvis`/`rka`，`clib`/`isCvi` 同单包）。
3. **生成原生模块**：`native-mods.js` 按该家族生成（cvis/rka = 仅 `updater`）。
4. **暂存**：`stageMergeFamily()` 清空 `ui/libs/`，生成
   - 架构兜底目录 `<架构>/`（官方 arch.md 的 fallback 语义）
   - 该家族全部官方代号目录 `<架构>-<代号>/`
   - bridge 用 strip 后的临时副本
5. **校验暂存**：根目录无平铺 so、目录名合法、每个目录文件清单与计划完全一致（多/少都报错）。
6. **打包**：`pnpm -C ui package`（`aiot-cli -c -q -p`）。
7. **搬运/校验**：产物改名到 `dist/miniapp-merged-<家族>-<版本>.amr`，校验 < 10MB。

全部结束后 `finally` 执行**收尾还原**：`res/version.js` = rk 默认、`native-mods.js` = rk、
`ui/libs/` = rk 单包平铺（构建失败也会还原）。因此构建完成后工作区始终可以直接
`pnpm -C ui package` 调试。

> `--stage --merge` 只做第 1~5 步、不打包也不还原，`ui/libs` 保留最后处理家族的暂存结构
> （默认顺序 cvis→rka，所以最后留下的是 rka 的 `arm/ arm-y09/ arm-y09p/`）。

### 7.1 已验证：目录命名与安装期扁平化

在 RK 真机上装**旧跨家族组合包**（`miniapp-merged-1.1.52.amr`，当时的 6 目录命名；

结果只剩 4 个**扁平化并追加数字后缀**的库：

```
libjsapi_Eric_371076449.so
libjsapi_panet_371076449.so
libjsapi_twofinger_371076449.so
libjsapi_updater_371076449.so
```

结论（**官方约定被真机证实**）：

1. PMS **按设备代号选中了 `libs/arm64-y02-1/`** —— 连字符目录名 `arm64-y02-1` 有效；
2. 选中后**把该目录整目录扁平化**到安装目录 `libs/`，并追加数字后缀；
3. 组合包能安装、应用能启动。

### 7.2 已验证：跨家族包的降级（所以不发布）

同一个包（JS 是 `merged`，`tryRequire` 懒加载）在 rk 上：

- 控制台出现 `[device] 无文件读取能力 (全局 readFile 与 fs 都不可用)`；
- device source 从 `hardware:config-file` 降为 `storage`；
- 原因：安装后库名被追加数字后缀（`libjsapi_panet_371076449.so`），
  运行期 `tryRequire('panet')` 取不到模块。

→ 跨家族组合包「能跑但降级」，因此只保留 `--merge-cross` 实验开关。

### 7.3 已验证：重构后 rk 单包正常（回归）

装重构后的 `rk/8001865309000007.1_1_52-rk.amr` 后日志正常：
`[native] panet(静态 import) -> ok`、`[device] source=hardware:config-file`、
DynamicLib 正常 dlopen 四个库。

## 九、排错

| 现象 | 原因/处理 |
|---|---|
| `[so平台预检失败] 缺少必需库` | `native/libs/<架构>-<代号>/` 缺库；先 `node native/build.mjs` 或补齐物料 |
| `[so平台预检失败] 当前 CPU 架构/libc 类型不符` | 库混错平台；换正确库，或确知正确时 `--skip-so-check`（风险自负） |
| `组合包需要 zig ... 找不到 zig.exe` | 放好 `_ref/zig/z/zig.exe` 或设 `ZIG_EXE` |
| `ui/libs/ 根目录出现平铺 .so` | 暂存目录被手工污染；重跑 `--stage --merge`（会自动清空重建） |
| `出现未在计划内的目录` / 文件清单不符 | 同上；不要手工往 `ui/libs/` 放文件 |
| 组合包 > 10MB | 检查是否误把未 strip 的库打进包；cvis bridge 未 strip 会直接超 |
| 装完应用白屏/原生全降级 | 确认装的是**同家族**的包；跨家族包必降级（见 §7.2） |
