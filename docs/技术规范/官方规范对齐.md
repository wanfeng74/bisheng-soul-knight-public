## 二、对官方「组合包」的适配与偏差

### 2.1 官方跨家族组合包的原理

官方 `build_merge()` 把多个设备代号的库目录打进同一个 amr，**依赖各代号使用同一套 JSAPI bridge
模块**：应用 JS 里 `import 'bridge'`（或 `require`）对所有代号都成立，运行期由框架/PMS 按设备
代号选中并解压对应目录的 so。也就是说：**一个 app.js.bin 能跨家族的前提是「各家族原生模块集合一致」。**

### 2.2 我们的偏差：按家族组包

本项目不满足上述前提：

| 家族 | 原生模块集合 | JS 侧 import |
|---|---|---|
| rk（aarch64/glibc） | panet + Eric + twofinger + updater | `import 'panet'` / `'Eric'` / `'updater'` |
| cvis（armv7/glibc） | bridge + updater | `import 'updater'`（bridge 不静态 import） |
| rka（armv7/uClibc） | bridge(uClibc) + updater | `import 'updater'` |

ESM 的 `import` 在模块求值前必须全部解析：rk 的 JS 写了 `import 'panet'`，装到 arm 机器上就整页白屏；
反之 arm 的 JS 到 rk 上会失去 panet（真机实测见下）。**静态 import 无法跨家族统一**，因此：

- **正式产物按家族出组合包**（`--merge`，默认 cvis + rka，每个家族一个 amr，JS 就是该家族单包）；
- 官方跨家族组合包能力保留为**实验开关** `--merge-cross`（输出 `dist/miniapp-merged-cross-<版本>.amr`），
  **不得作为正式产物发布**。

### 2.3 偏差清单（引用时必须知道）

| # | 偏差 | 说明 | 影响 |
|---|---|---|---|
| D1 | **没有 aarch64 版 `libjsapi_bridge.so`** | 官方规范中 `arm64-orange`/`arm64-y02-1` 两行都构建 bridge，我方没有实物/源码；rk 一直用 panet（系统 `libjsapi_export*` 的复制改名）+ Eric | rk 家族包只能放 panet/Eric，不是「统一 bridge」；要统一必须向提供方索取 aarch64 bridge 或 `jsapi/` 源码 |
| D2 | **`panet` 是 RK 私有/系统库副本** | 全部参考文档中 `panet` 出现 0 次；它是固件公共 JSAPI（`/etc/miniapp/jsapis/libjsapi_export*.so`）的复制改名 | 不能在非 RK 家族使用，也不能当 bridge 用 |
| D3 | **`rka`（y09/y09p）不在官方 4 代号内** | 官方代号只有 orange/y02-1/coco/plum；`rka` 是 A 系列（A6/A7）的工程命名 | 组合包目录 `arm-y09*` 是**超出官方约定的扩展**，能否被 PMS 识别未经官方文档确认 |
| D4 | **单包不 strip** | 官方要求库产物 strip 后放置；当前只有组合包暂存时对 bridge 做 `objcopy --strip-all`，单包保留原始库 | cvis 单包 3.71MB（bridge 5.86MB 未 strip）；如需减小可给单包也加 strip，但会改变已交付包形态，需评估 |
| D5 | **默认不做跨家族组合包** | 因 D1/D2 + ESM 静态 import 限制（见 §二.2、§三真机记录） | 用户跨家族换机仍需装对应家族包；换来的是原生能力不降级 |
| D6 | **`TARGET_SKU` 不进 C++ 代码** | 官方规范明确 `-DTARGET_SKU` 仅用于区分目录；本项目 profile 仅用它选库目录 | 同架构同 libc 的代号库产物实际相同；不必为每个代号编一份 |

### 2.4 已对齐（无偏差）的部分

- 代号目录命名 `<架构>-<代号>`（连字符）：**已由 RK 真机验证 PMS 接受**（见 §三）。
- 组合包根目录禁止平铺 so、按代号目录打包、架构兜底目录：已实现并通过构建校验。
- `version.js` 官方字段（clib/isCvi/nowVersion/buildCode/appid/updateDir）：已对齐。
- 构建期 env（`CROSS_TOOLCHAIN_PREFIX/LOLIAPP_CLIB/ISCVI/TARGET_SKU`）：`native/build.mjs` 识别。
- `--release` patch 递增：已实现。

## 三、真机验证记录（2026-10-19，RK Y02-1）

> 原始记录：`D:\PROJECT2\_load\device-verify-20261019.md`（SSH 通道
> `ssh -i D:\PROJECT2\_dev\ssh\pen_id -p 2222 root@<SERVER_IP>`）。
> 设备：YoudaoDictionaryPen-484 / Rockchip RK3562 Y02-1 / aarch64 / glibc 2.36。

### 3.1 实验 1：旧跨家族组合包（6 目录，含 arm64-y02-1）

- 上传 md5 一致，`miniapp_cli install` 返回 `ret=0`，启动 `ret=0`，应用能运行。
- **关键证据**：安装后 `.../pkg/8001865309000007/a/libs/` 只剩 4 个**扁平化并追加数字后缀**的库：
  `libjsapi_Eric_371076449.so / libjsapi_panet_371076449.so /
  libjsapi_twofinger_371076449.so / libjsapi_updater_371076449.so`。
  → **PMS 按设备代号选中了 `libs/arm64-y02-1/`（连字符目录名有效），并把该目录整目录扁平化**。
  → 官方「运行时/安装期自动选目录」在 y02-1 上成立；目录分隔符连同字符已确认可用。
- **但原生能力降级**：控制台出现 `[device] 无文件读取能力 (全局 readFile 与 fs 都不可用)`，
  device source 从 `hardware:config-file` 降为 `storage`；即跨家族包的 merged JS 里
  `tryRequire('panet')` **拿不到模块**（安装后库名带数字后缀，运行期 require 不按 header 解析）。

### 3.2 实验 2：重构后的 rk 单包（回归）

- `rk/8001865309000007.1_1_52-rk.amr` 安装/启动均 `ret=0`；日志：
  `[native] panet(静态 import) -> ok`、`panet.readFile 返回 Promise`、
  `[device] sn=... source=hardware:config-file`、`[srv] 状态=正常`；
  DynamicLib 正常 dlopen `libjsapi_panet/twofinger/Eric/updater_371076449.so`。
- 结论：版本模块/平台判定/原生模块懒加载改造**没有破坏 rk 行为**；rk 单包可作为稳定产物。

## 五、后续开发指引

### 5.1 新增一个机型代号

1. 在 `scripts/profiles.mjs` 对应 profile 的 `codes` 数组加入代号（若是新家族则新增 profile）。
2. 在 `ui/src/services/platform.js` 的 `FAMILY_CODES` 加入「代号 → 家族」。

4. 跑 `pnpm -C ui test`（含 `test-platform`/`test-profiles`/`test-merge-family`）。

   （架构 + libc 必须匹配 profile，否则拒绝打包）。
