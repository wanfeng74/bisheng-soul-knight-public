# 开发规范

## 一、版本管理

- **唯一版本入口**：`ui/package.json` 的 `version`。
- `ui/src/res/version.js` 是 `scripts/gen-ui-version.mjs` 生成的构建产物，**禁止手改**：
  字段 `clib / isCvi / nowVersion / buildCode / appid / updateDir / platform / VERIFY_BUILD`
  （兼容字段 `APP_VERSION / APP_ID / BUILD_TARGET`）。
- `ui/src/services/version.js` 只是兼容层（re-export 版本字段 + `ADMIN_PASSWORD`），
  新代码直接从 `../res/version.js` 取字段；平台判定用 `./platform.js`。
- 发版递增：`node scripts/build-amr.mjs --release`（patch 位 +1，等价
  `npm version patch --no-git-tag-version`）；手工改 `ui/package.json` 后也可，
  但**不要再手工同步 `services/version.js`**（它已不存版本号）。
- 生成物清单（都不要手改）：
  - `ui/src/res/version.js`
  - `ui/src/services/native-mods.js`
  - `ui/libs/`（构建暂存目录）

## 二、官方平台约定（profile / ISCVI / CLIB）

依据 `_ref/docs2/组合包打包规范.md` 与 POSC 官方文档，本项目落地在 `scripts/profiles.mjs`：

| 官方约定 | 本项目实现 |
|---|---|
| 设备用**代号（codename）**标识 | `PROFILES`：`rk`(y02-1/orange)、`cvis`(coco/plum)、`rka`(y09/y09p) |
| 库放 `ui/libs/<架构>-<代号>/` | 物料源放 `native/libs/<架构>-<代号>/`；`ui/libs/` 是构建暂存 |
| 构建期 env `CROSS_TOOLCHAIN_PREFIX / LOLIAPP_CLIB / ISCVI / TARGET_SKU` | `native/build.mjs` 识别并作为 profile 覆盖；`build-amr.mjs` 用 `--targets` 等价选择 |
| `ISCVI`：aarch64=false，armv7=true | profile 的 `isCvi` 字段（rk=false，cvis/rka=true） |
| `TARGET_SKU` 不进 C++ 代码，只区分目录 | 仅用于 `native/build.mjs` 选 profile / 目录 |
| 库产物 strip 后放置 | 组合包暂存阶段用 `_ref/zig/z/zig.exe objcopy --strip-all` 处理 bridge 副本 |
| 版本文件 `ui/src/res/version.js` | `scripts/gen-ui-version.mjs` 生成 |

- **历史别名**：`cvia` → `rka`。构建/客户端/服务端都必须继续识别（老包、老配置、服务端接口）。
- 新增机型时改三处：`scripts/profiles.mjs`（若属新家族）、
  `services/platform.js` 的 `FAMILY_CODES`（代号→家族）、组合包暂存的代号目录列表。

## 三、原生模块 import 规则（最容易白屏的地方）

1. **静态 `import ... from 'panet'/'Eric'/'updater'` 只允许出现在
   `ui/src/services/native-mods.js`**（由构建按目标生成）。
   ESM 静态解析发生在模块求值前：包里缺对应 `.so` 时整页白屏，`try/catch` 拦不住。
2. 业务代码只通过 `getPanet()` / `getEricShell()` / `updater` 取模块；
   `native.js`、`appinstall.js`、`downloader.js` 已按此改造。
3. **组合包运行期懒加载**走 `services/optional-native.js` 的 `tryRequire(name)`：
   - 只能在**普通 `.js` 模块的函数体内** `require`；
   - `.vue` 的 `<script>` 里写 `require(...)` 会被构建器静态提升成顶层 import → 真机黑屏
     （v1.0.55 事故根因，`native-twofinger.js` 是已验证的正确写法）。
4. 四目标生成内容（`scripts/native-mods-content.mjs`，测试锁死）：
   - `rk`：panet + Eric + updater 静态 import
   - `cvis`：只 import updater
   - `rka`：只 import updater
   - `merged`：updater + 运行期 `tryRequire('panet'/'Eric')`
   - `unknown`：全部 null（兜底，宁缺不白屏）
5. 修改生成逻辑后必须跑 `ui/scripts/test-native-mods.mjs`（四目标逐项断言）。

## 四、组合包约束

- 组合包**按家族**出（官方跨家族单包在 RK 真机会导致原生能力降级，只留 `--merge-cross` 实验开关）：
  - cvis 家族包：`arm/` + `arm-coco/` + `arm-plum/`，JS 为 cvis 单包；
  - rka 家族包：`arm/` + `arm-y09/` + `arm-y09p/`，JS 为 rka 单包；
  - rk 家族包（可选）：`arm64/` + `arm64-orange/` + `arm64-y02-1/`，JS 为 rk 单包。
- 默认家族集是 `cvis + rka`（`--merge`）；`--merge-targets` 可指定（可含 rk）。
- 组合包模式下 `ui/libs/` 根目录**不得有任何 `.so`**；`libjsapi_bridge.so` 只能在
  `<架构>-<代号>/` 子目录内；目录名必须来自 profile 的官方代号集；构建脚本会逐项校验。
- `libjsapi_bridge.so` 放进包前必须 strip（zig objcopy 副本，源库不动）；rk 库不 strip。
- 组合包目标体积 < 10MB（脚本硬校验）。
- 跨家族实验包（`--merge-cross`，`dist/miniapp-merged-cross-<版本>.amr`）**不得发布**。
- 具体命令、目录布局与校验见 [组合包打包.md](组合包打包.md)；
  官方约定与偏差见 [官方规范对齐.md](官方规范对齐.md)。

## 五、ES5 / QuickJS 约束

- 纯 ES5 风格（`var` / `function` / 原型），兼容 QuickJS 20200705；
  不用箭头函数、模板字符串、可选链、解构。
- 真机 `getContext` 必须在 `mounted` 后获取，禁止递归。
- `textBaseline` / `strokeRect` / `arc` 不支持。
- 无 `document` / `requestAnimationFrame` / `localStorage`：精灵直接画主上下文，
  循环用 `setInterval(16ms)`，存储用 `jsapi.storage`。
- 定时器全局可用，页面实例无 `setInterval`（用 BasePage 托管并统一释放）。
- 页面生命周期钩子必须写在 `methods` 内（见 HANDOVER 红线 14）。

## 六、CSS 约束

- falcon-ui 仅支持单类名选择器，禁止 `.class1.class2` 复合选择器。
- `border-radius` 仅支持单值，禁止 `6px 6px 0 0` 简写。
- 使用 `:class` 动态切换独立类名代替复合选择器。
- 模板用到的 class 必须有样式（`tools/check-css-classes.mjs` 会查）。

## 七、构建

```bash
pnpm -C ui install                       # 安装依赖

# 生成物/暂存（调试用）
node scripts/gen-ui-version.mjs --target rk
node scripts/stage-libs.mjs --target rk
node scripts/build-amr.mjs --stage rk
node scripts/build-amr.mjs --stage --merge

# 单包
node scripts/build-amr.mjs               # 三平台单包（rk/cvis/rka）
node scripts/build-amr.mjs --targets rk
node scripts/build-amr.mjs --targets rk,cvis --verify
node scripts/build-amr.mjs --release --targets rk
node scripts/build-amr.mjs --skip-so-check
node scripts/build-amr.mjs --help

# 组合包（按家族；默认 cvis + rka）
node scripts/build-amr.mjs --merge
node scripts/build-amr.mjs --merge --merge-targets cvis,rka,rk
node scripts/build-amr.mjs --merge-cross     # 跨家族实验，勿发布
```

- 构建结束 `finally` 会还原 rk 默认（`res/version.js` / `native-mods.js` / `ui/libs`），
  工作区始终可继续 `pnpm -C ui package` 调试。
- so 平台预检不可随意跳过：固件按包内 `.so` 的 libc 类型识别机型系列，
  混错 libc 会被识别成错误系列（历史事故）。确知库正确时才 `--skip-so-check`。

## 九、代码结构

- 业务逻辑放 `services/`，页面只做 UI 和事件绑定。
- 全局状态用 `$falcon.__deltaDb` / `$falcon.__deltaCfg` / `$falcon.__deltaResult`
  / `$falcon.__deltaHidden`。
- 页面间导航：`$falcon.navTo(page, {})` / `this.$page.finish()`。
- 数据生成器在项目外 `D:\PROJECT2\_tools\`；改物品/地图数据要改生成器再重新生成，
  不要在运行时文件里手改。
